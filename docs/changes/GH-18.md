**Puntos *(ambiguo)* y *(asumido)* del refinamiento:**

1. *(ambiguo)* **Qué es «instalar» hoy.** El paquete es privado y no se publica en npm, así que el procedimiento parte de un clon del repositorio: `git clone`, `npm install`, `npm run build` y `npm link` (o `npm install -g .`). Propuesta: documentar `npm link`, que es lo que ya recoge `CLAUDE.md`. Alternativa: `npm install -g .`, que en GH-17 se comprobó en WSL (crea un enlace equivalente).
2. *(ambiguo)* **El procedimiento aún no se ha probado en Windows.** En GH-17 se comprobó `build`, el enlace y el `.tgz` en WSL; el `.cmd` que npm genera en Windows y `npm link` real quedan para los issues #19 y #20. Propuesta: escribir el procedimiento ya y añadir una línea honesta («verificado en WSL; la comprobación en Windows está pendiente»), que se quita al cerrar #20. Alternativa: no añadir el aviso.
3. *(asumido)* **Los dos documentos llevan los mismos pasos.** `docs/001` §1.4 con el detalle (requisitos, instalación, primer arranque, dónde se guarda cada cosa, cómo actualizar y qué hacer si algo falla) y `README` §1.4 con la versión breve de los mismos pasos, que enlaza a `docs/001`. Así los dos cumplen el criterio y el test puede vigilar ambos sin que se separen.
4. *(asumido)* **Contenido que se añade, además de los pasos:** que la base `devflow.db` y las migraciones se crean solas en el primer arranque (no hay semillas de datos), dónde se guardan la base (`%APPDATA%\DevFlowCLI\`) y los tickets (`%USERPROFILE%\DevFlowCLI\tickets\`), cómo obtener el modelo (`ollama pull qwen2.5:3b`) y el aviso de memoria (8 GB con IDEs abiertos), y cómo actualizar (`git pull`, `npm install` y `npm run build`).
5. *(asumido)* **La nota del API Token en claro** (decisión del MVP, `docs/002` §2.5) se incluye en las instrucciones de instalación, como quedó anotado al recortar el issue el 2026-11-13.
6. *(asumido)* **Test de coherencia de documentos** (`tests/unit/docs/install-instructions.test.ts`): lee las secciones por su encabezado y solo comprueba presencia y coherencia (comandos que existen en `package.json` y en el programa, H-05 marcado ✅). Hay antecedente en el repo (`tests/unit/gitignore.test.ts` y `tests/unit/lint-rules.test.ts` comprueban archivos del propio proyecto). El riesgo es la fragilidad ante cambios de formato en los documentos.
7. *(asumido)* **«Resuelto» para H-05** significa instrucciones escritas y token en claro decidido; la verificación en Windows sigue en #19 y #20 y se anota, no bloquea.

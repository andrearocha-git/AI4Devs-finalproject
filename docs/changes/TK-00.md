# Change: TK-00 — Scaffold del proyecto Node.js + TypeScript

- **Estado:** Implementado
- **Fuente:** `docs/006-tickets-de-trabajo.md` (TK-00)
- **Depende de:** ninguna
- **INVEST:** Cumple (I, S y T evaluadas)

## Propósito

Crear en la raíz del repo el armazón mínimo (TypeScript `strict`, Vitest, ESLint, `.gitignore`) para poder ejecutar `typecheck`, `lint` y `test`.
Habilita a TK-01 a TK-03 y deja verificables las reglas de acoplamiento de capas desde el primer commit de código.

## Criterios de aceptación de origen

- CA1: `npm install` termina sin errores y `package.json` declara `engines.node >= 22.13`.
- CA2: `npm run typecheck` termina con código 0 sobre el proyecto sin código de aplicación.
- CA3: `npm test` ejecuta Vitest y pasa con `tests/unit/smoke.test.ts` (Node en ejecución ≥ 22.13).
- CA4: `npm run lint` termina con código 0 y excluye `docs/` y `.claude/`.
- CA5: importar `node:sqlite` fuera de `src/database/sqlite-storage-manager.ts`, o `src/database/` desde `src/tui/`, hace fallar `npm run lint`.
- CA6: `.gitignore` excluye `node_modules/`, `dist/` y `coverage/`.

## Escenarios BDD

### E1 — Instalación y comandos base operativos (cubre: CA1, CA2, CA3)

- **Given** un repo con `package.json`, `tsconfig.json` y `vitest.config.ts`, sin código de aplicación
- **When** se ejecutan `npm install`, `npm run typecheck` y `npm test`
- **Then** los tres terminan con código 0, `engines.node` es `>= 22.13` y el test de humo confirma que Node en ejecución es ≥ 22.13

### E2 — Lint con exclusiones y reglas de capas (cubre: CA4, CA5)

- **Given** la configuración de ESLint con exclusiones y reglas de importación restringida
- **When** se ejecuta `npm run lint` sobre el proyecto limpio, y sobre código que importa `node:sqlite` fuera de `sqlite-storage-manager.ts` o `src/database/` desde `src/tui/`
- **Then** el proyecto limpio termina con código 0 sin analizar `docs/` ni `.claude/`, y el código con la importación prohibida hace fallar el lint

### E3 — Artefactos generados fuera del control de versiones (cubre: CA6)

- **Given** un `.gitignore` en la raíz
- **When** existen las carpetas `node_modules/`, `dist/` y `coverage/`
- **Then** Git las ignora y no aparecen en `git status`

## Prerrequisitos

- Ninguno pendiente. Al comenzar no existían `package.json`, `tsconfig.json`, `vitest.config.ts`, `eslint.config.js`, `.gitignore`, `src/` ni `tests/`: eran justamente el objeto de este cambio y ya fueron creados.
- **Quién ejecuta este cambio: resuelto.** `/04-tdd-pair` solo puede escribir en `src/` y `tests/`, no crea el scaffold y no modifica `CLAUDE.md`, pero este ticket crea configuración en la raíz y su DoD exige actualizar `CLAUDE.md`. Se decidió la opción A: lo implementa Claude fuera de la skill, siguiendo este contrato (ver Decisiones y desvíos).
- **CA5 "verificado a mano": resuelto.** El ticket decía que se probaba con un archivo temporal que luego se elimina. Se acordó un test automatizado `tests/unit/lint-rules.test.ts` que usa la API de ESLint (`lintText`) para comprobar que la regla falla con la importación prohibida, sin archivos temporales (ver Decisiones y desvíos).
- Nota: `tsc --noEmit` falla si no encuentra ningún archivo de entrada (TS18003), por eso `tsconfig.json` debe incluir `tests/` además de `src/`. Una carpeta `src/` vacía no se versiona en Git, así que se propone `src/.gitkeep`.

## Criterios de aceptación de origen

- CA1: dar de alta la clave de un proyecto la valida contra Jira, guarda la clave con el nombre del proyecto y confirma que quedó lista.
- CA2: una clave inexistente se rechaza con el motivo; si el rechazo es por token inválido, lo dice en lugar de decir que la clave no existe.
- CA3: asociar un repositorio (nombre, ruta, rama base `main` por defecto) verifica que sea un repositorio Git con remoto `origin` y que la rama base exista en el remoto; si falla, rechaza con el motivo. Una clave puede tener 0, 1 o varios repositorios.
- CA4: el sufijo de usuario se propone desde el nombre de la cuenta de Jira (inicial del nombre más último apellido, sin acentos, en mayúsculas); se puede confirmar o editar y se guarda para todas las ramas.
- CA5: actualizar una clave o un repositorio reemplaza el valor anterior y no deja una configuración duplicada.
- CA6: sin ninguna clave dada de alta, iniciar un ticket avisa que primero hay que configurar al menos una.

## Escenarios BDD

### E1 — Alta de claves de proyecto y rechazo con motivo (cubre: CA1, CA2)

- **Given** que la herramienta tiene credenciales de Jira guardadas y todavía no hay claves dadas de alta
- **When** el usuario da de alta una clave que existe y, después, una que no existe o con un token que Jira rechaza
- **Then** la clave existente se valida contra Jira, se guarda en mayúsculas con el nombre del proyecto y se confirma que quedó lista; la inexistente se rechaza con su motivo, y si el 404 se debe a un token inválido (`/myself` da 401) el mensaje habla del token y no dice que la clave no existe

### E2 — Repositorios asociados, validados y sin duplicados (cubre: CA3, CA5)

- **Given** una clave de proyecto ya dada de alta
- **When** el usuario le asocia un repositorio (con rama base por defecto `main`), repite el alta o edita su ruta o rama base, o indica uno que no es repositorio Git, sin `origin` o con una rama base que no existe en el remoto
- **Then** solo se guarda el que pasa la validación de Git; los rechazos explican el motivo (carpeta que no es repositorio, falta `origin`, rama base inexistente) sin escribir nada; y actualizar un repositorio existente reemplaza ruta y rama conservando el mismo registro, sin duplicarlo; una clave admite 0, 1 o varios repositorios

### E3 — Sufijo de usuario y aviso de «sin claves» (cubre: CA4, CA6)

- **Given** un primer arranque con credenciales de Jira y sin claves dadas de alta
- **When** el usuario ejecuta `devflow config` y después intenta `devflow start` con una clave
- **Then** el sufijo se propone desde el nombre de la cuenta de Jira (p. ej. «Andrea Rocha» → `AROCHA`, sin acentos y en mayúsculas), se puede editar y se guarda; y `devflow start` avisa «primero configura una clave» (indicando `devflow config proyectos`) sin consultar a Jira ni iniciar el flujo

## Criterios de aceptación de origen

- CA1: sin indicar un ID, la herramienta muestra la lista de mis tickets abiertos asignados (sin épicas) para elegir uno.
- CA2: con el ID de un ticket que existe y con conexión, obtiene título, descripción y tipo, y continúa sin pedir nada más.
- CA3: un ID cuya clave no está dada de alta avisa, antes de consultar a Jira, que esa clave no está configurada y muestra las claves disponibles.
- CA4: sin conexión o con credenciales inválidas, avisa del motivo (distinguiendo credenciales inválidas de falta de conexión) y permite ingresar a mano título y descripción para continuar.
- CA5: un ID que no existe en Jira informa que no se encontró el ticket y ofrece cargar los datos a mano.
- CA6: una épica avisa que las épicas no se usan para desarrollar y no tienen plantilla, no crea rama ni documento e invita a elegir una historia, tarea o bug.

## Escenarios BDD

### E1 — Elegir de la lista y consultar el ticket (cubre: CA1, CA2)

- **Given** claves de proyecto dadas de alta y tickets abiertos asignados al usuario en Jira
- **When** el usuario ejecuta `devflow start` sin ID, elige un ticket de la lista, o ejecuta `devflow start <ID>` con el ID de un ticket existente
- **Then** la lista trae solo los tickets abiertos asignados y sin épicas; y para el ticket elegido o indicado se obtienen título, descripción y tipo (`bug` o `historia`) y el flujo continúa sin pedir más datos que la confirmación única del flujo

### E2 — Fallback manual por fallo de Jira (cubre: CA4, CA5)

- **Given** que Jira no responde, o rechaza el token, o no encuentra el ticket
- **When** el usuario inicia el ticket
- **Then** la herramienta informa un motivo distinto para cada caso (sin conexión, credenciales inválidas y ticket no encontrado; un 404 se contrasta con `/myself`, así que un token inválido nunca se presenta como «no existe») y pide título y descripción a mano (con el tipo `bug` solo si se marca), y el flujo continúa con esos datos

### E3 — Bloqueos antes de actuar: clave no configurada y épica (cubre: CA3, CA6)

- **Given** un ID cuya clave no está dada de alta, o un ticket de Jira que es una épica
- **When** el usuario inicia el ticket
- **Then** con la clave no configurada se avisa, sin llamar a Jira, y se listan las claves disponibles; con la épica se avisa que no se usan para desarrollar ni tienen plantilla, sin pedir confirmación y sin crear rama, carpeta, documento ni fila en `ticket_logs`

CA4: sin conexión (`network_timeout`) y credenciales inválidas (`invalid_token`) dan motivos distintos, y el Orquestador pide título y descripción a mano y continúa (`source: "manual"`, rama creada y fila `jira_fetch_status = fallback_manual` con el motivo en `jira_fetch_error`). Un error bloqueante de Jira (respuesta inesperada) corta el flujo sin pedir nada ni crear nada: es el único caso en que no hay carga manual, y no lo cubren los CA4 ni CA5.
- **2026-11-15 — E3 cerrado sin cambios de código:** 5 tests pasan en los 3 archivos filtrados, y `summary-view.test.ts` aporta el encabezado de la épica.
